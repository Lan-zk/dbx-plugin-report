# 产品范围与决策规则

来源：`docs/product/scope.md`、`docs/product/decisions.md`、`docs/product/naming.md`、`docs/README.md`。基线见 `docs/README.md:4`。**所有决策状态按原文保留，不得升格。**

## 1. 定位（I）

作者写固定 SQL，把查询结果做成可重复打开的报表，再组合成小看板；资产是本机 JSON 文件。**不是**自助 BI、语义层、团队共享或自动发布平台（`docs/README.md:10`）。首版服务"会写、能审 SQL 的人"，不是业务人员自助拖拽分析（`docs/product/scope.md:12`）。

## 2. 首版承诺（`docs/product/scope.md:16-27`，状态：分析结论待确认）

| 维度 | 内容 |
|---|---|
| 平台 | DBX 桌面端，UI-only 插件（无 sidecar、无后端） |
| 连接 | 单文档一个逻辑连接；打开时由人映射到本机 `connectionId`；SQLite / PostgreSQL 为认证候选 |
| 数据 | 每条查询一条作者固定 SQL；数据库侧聚合；默认 500 行、最高 5000 行；手动刷新 |
| 资产 | 本机 JSON 定义文件（打开/另存）；一个文档内 datasets / reports / dashboards |
| 呈现 | 表格、柱状图、折线图、数值卡；一个看板最多 4 张报表 |
| 导出 | 当前已验证结果的 CSV；JSON 定义导出 |
| AI | 可选：生成单报表候选 JSON，人工审阅、预览、确认后保存；不自动发布 |
| 语言/主题 | 跟随宿主 locale 与主题；中英文文案 |

**不承诺**多数据库通用支持；未通过真实数据库验收前不得对外标"支持"（`scope.md:27`）。

## 3. 明确不做（范围栅栏，`scope.md:40-50`）

自助分析/任意换维/跨模型 join；完整语义层或语义编译器；跨连接联邦查询与客户端 JOIN；SQL 参数拼接、自由文本/标识符/表达式插槽；写语句、DDL/DML、存储过程、多语句、临时表、锁定读；分页明细、海量导出、长任务后台执行、无人值守调度/订阅；团队 ACL、公开分享、审计合规平台、商业定价；复制数据库凭据、绕过宿主授权、自建数据库驱动；通用跨方言 SQL 翻译、打印排版引擎。

## 4. 产品不变量 8 条（`scope.md:54-61`，原文关键句）

1. **SQL 是计算真相，指标词典是解释真相。** 词典只描述 SQL 输出字段，不生成 SQL。
2. **作者负责口径，读者只操作作者预设的结果过滤/排序。**
3. **AI 只交候选，人工确认才保存**；不自动发布、不自动扩大权限。
4. **本机 JSON 文件是正式资产**；`host.storage` 只存偏好和有限草稿，不存业务结果。
5. **截断不是完整。** `truncated=true` 只可样本预览，不允许作为正式总计或标记"完整"导出。
6. **保存是显式动作。** 取消保存对话框不得显示"已保存"；关闭窗口不保证自动持久化。
7. **刷新不是事务快照。** 看板内多查询无一致性事务，必须显示每张卡取数时间，不能给单一"截至时间"假象。
8. **只读分类不是权限。** 只读合同不能替代数据库最小权限账号；不把分类器当副作用证明。

## 5. 成功标准与止损（`scope.md:76-85`）

- 成功（M1/M2 后验证）：同文档可重复打开/重新绑定/重新取数，结果与独立 SQL 客户端一致；**2 名目标作者**在无开发协助下完成"SQL→报表→保存→重开"并愿意继续用；截断/失败/取消/断连都有明确状态，无"假完整/假保存"。
- 止损 1：目标用户不能写/审 SQL，或拒绝本机文件 + 显式另存 → 停当前 MVP，重做立项。
- 止损 2：UI-only 沙箱无法稳定完成图表+查询+保存闭环，且不能在不降低安全门槛下解决 → 停止方案。
- 止损 3：出现未授权写入/外发，或错误/截断结果被标为正式完整 → 冻结发布并回归。
- 止损 4：AI 未达 V4 门槛 → 移除 AI 承诺，保留手工工具。

## 6. 决策状态（不得提升）

### ADR-01~04：全部**暂定**（分析报告建议，未书面确认，`decisions.md:6-36`）

| ADR | 决定 | 复议条件 |
|---|---|---|
| ADR-01 | SQL 是计算真相；词典只描述输出字段（单位、可加性、时间口径、NULL 策略），不生成 SQL、不做跨模型 join | 大量"必须自助换维度"用户且愿承担语义层成本 → 另立项 |
| ADR-02 | 作者写/审 SQL；读者只操作作者预设的结果过滤、排序、Top N | 目标用户不能写 SQL 或首版演练失败 → 停止当前 MVP |
| ADR-03 | AI 生成受限 JSON/SQL 候选，经 schema/字段/版本/语法检查，作者审阅 + `queryData` 预览后人工确认保存 | V4 达门槛且 V5 通过 → 可讨论更自动流程，仍需人工确认口径 |
| ADR-04 | ProjectDocument JSON 是正式资产，经 `host.saveFile` 另存；打开需用户选文件/重新绑定；`host.storage` 只存偏好与有限草稿 | 用户拒绝文件式体验且接受新增宿主资产 API 成本 → 重新裁决 |

### D1–D5：**待定**，会阻塞里程碑（`decisions.md:40-48`）

| ID | 决策 | 建议默认 | 决策门时点 |

### 评审已确认 5 条（2026-10-22，`decisions.md:50-58`，"仍以 ADR 为准"）

1. 边界由宿主硬限制反推，不靠竞品功能清单；证据抽查 10 处与 `b160d130` 一致。
2. 先做 walking skeleton，再"单报表竖切"；看板、AI、PostgreSQL 后置。
3. AI 不阻塞首发；V4 不达标则移除 AI 承诺。
4. 图表库在 M0 实测后再定（ECharts / 轻量 SVG），不先绑 Vega-Lite。
5. 首版不新增 Host API；bind/cancel/分页/资产 API 作为宿主路线图输入正式提出，不在插件侧伪装支持。

## 9. 反模式（`docs/reference/methodology.md:61-67`）

把竞品功能清单当需求；把 README/博客当能力证明；把版本号当能力；用"以后可能需要"引入抽象/扩展点/后端；在里程碑里悄悄扩大范围；把未验证的 AI/图表说成已支持；用"测试全绿"替代真机集成；用"没报错"替代安全验证；把截断/失败结果包装成"完整/最新"。
