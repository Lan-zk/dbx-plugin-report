# 产品范围（Scope）

> 状态：分析结论，待负责人确认（见 [decisions.md](decisions.md)）。  
> 依据：[analysis/feasibility-report.md](../analysis/feasibility-report.md)、[host/capabilities.md](../host/capabilities.md)。

## 定位

**面向 SQL 作者的本地报表工具，作为 DBX 桌面插件运行。**

作者把一条固定 SQL 保存为数据集，选择输出字段、图表和说明，形成可重复打开的报表；多个报表可组合成同连接的小看板。资产以本机 JSON 文件保存和分享，打开时由使用者重新绑定本机连接并重新授权。

首版服务的是“会写、能审 SQL 的人”，不是业务人员自助拖拽分析。

## 首版 MVP（承诺范围）

| 维度 | 首版内容 |
|---|---|
| 平台 | DBX 桌面端，UI-only 插件（无 sidecar、无后端） |
| 连接 | 单文档一个逻辑连接；打开时由人映射到本机 `connectionId`；SQLite / PostgreSQL 为认证候选 |
| 数据 | 每条查询一条作者固定 SQL；数据库侧聚合；默认 500 行、最高 5000 行；手动刷新 |
| 资产 | 本机 JSON 定义文件（打开/另存）；一个文档内 datasets / reports / dashboards |
| 呈现 | 表格、柱状图、折线图、数值卡；一个看板最多 20 张报表（建议 ≤12），在 12 列网格内自由拖拽/缩放、可调宽高与尺寸预设（非像素级画布） |
| 导出 | 当前已验证结果的 CSV；JSON 定义导出 |
| AI | 可选：生成单报表候选 JSON，人工审阅、预览、确认后保存；不自动发布 |
| 语言/主题 | 跟随宿主 locale 与主题；中英文文案 |

首版**不承诺**多数据库通用支持；未通过真实数据库验收前不得对外标“支持”。

## 后续（不进首版）

- Dock 面板、浮窗常驻只读看板（先验证多实例、关闭恢复、CSP）。
- PNG/SVG 导出、PDF 分页排版（后者是独立排版需求，未证实必需）。
- SQL 绑定参数（需宿主新增 bind API，或通过认证的类型编译路线并通过注入测试）。
- MySQL 等更多数据库（逐库增加方言/数字/超时/权限黄金语料）。
- 内置 Agent 直接写草稿的组合路径（需先做 V5 spike，并确认 sidecar 成本）。
- 指标词典的更完整语义（仍不自建语义编译器）。

每项重启条件写在 [decisions.md](decisions.md) 与 [development/roadmap.md](../development/roadmap.md)。

## 明确不做（范围栅栏）

- 自助分析：任意维度组合、自动换维、跨模型 join。
- 完整语义层/语义编译器（MetricFlow、Cube 类）。
- 跨连接联邦查询；客户端抓明细后本地 JOIN。
- SQL 参数拼接、自由文本/标识符/表达式插槽。
- 写语句、DDL/DML、存储过程、多语句、临时表、锁定读。
- 分页明细、海量导出、长任务后台执行；无人值守调度/订阅。
- 团队 ACL、公开分享服务、审计合规平台、商业定价。
- 复制数据库凭据、绕过宿主授权、自建数据库驱动。
- 通用跨方言 SQL 翻译、打印排版引擎。

## 产品规则（不变量）

1. **SQL 是计算真相，指标词典是解释真相。** 词典只描述 SQL 输出字段，不生成 SQL。
2. **作者负责口径，读者只操作作者预设的结果过滤/排序。**
3. **AI 只交候选，人工确认才保存；不自动发布、不自动扩大权限。**
4. **本机 JSON 文件是正式资产；** `host.storage` 只存偏好和有限草稿，不存业务结果。
5. **截断不是完整。** `truncated=true` 只可样本预览，不允许作为正式总计或标记“完整”导出。
6. **保存是显式动作。** 取消保存对话框不得显示“已保存”；关闭窗口不保证自动持久化。
7. **刷新不是事务快照。** 看板内多查询无一致性事务，必须显示每张卡取数时间，不能给单一“截至时间”假象。
8. **只读分类不是权限。** 只读合同不能替代数据库最小权限账号；不把分类器当副作用证明。

## 用户与角色

| 角色 | 首版职责 |
|---|---|
| SQL 作者 | 写/审 SQL，定义输出字段与指标口径，确认版本，保存文档 |
| 本机使用者 | 打开文档、重新绑定连接、授权查询、切换作者预设视图、导出当前结果 |
| 连接管理员 | 提供只读/最小权限账号，批准插件访问（首版可与作者同一人） |
| 插件维护者 | 文档格式、依赖、版本兼容、发布与安全 |

首版不构造不存在的 RBAC；角色可以是同一个人。

## 成功标准与止损

**成功（M1/M2 后验证）**：
- 同一份文档可重复打开、重新绑定、重新取数，结果与独立 SQL 客户端一致。
- 2 名目标作者在无开发协助下完成“SQL → 报表 → 保存 → 重开”流程，并愿意继续使用。
- 截断、失败、取消、断连都有明确状态，不产生“假完整/假保存”。

**止损（kill）**：
- 目标用户不能写/审 SQL，或拒绝本机文件 + 显式另存的工作方式 → 停止当前 MVP，重做立项（不是加语义层硬撑）。
- UI-only 沙箱无法稳定完成图表渲染 + 查询 + 保存闭环，且不能在不降低安全门槛的前提下解决 → 停止方案。
- 出现未经授权的写入/外发，或错误/截断结果被标为正式完整 → 冻结发布并回归。
- AI 未达到 3.4 节门槛 → 移除 AI 承诺，保留手工工具，不让 AI 拖累首发。

## 与 DBX 的关系

宿主提供：iframe 沙箱 UI、workbench/dock/浮窗/result-view 载体、连接列表与授权、`host.queryData` 只读 SQL 执行、单表列元数据、文件保存、UI 存储、AI completion、打包/签名/商店。

插件负责：报表/看板对象模型、SQL 作者工作台、图表渲染、指标词典、文档格式与校验、本机文件读写、刷新队列、错误与降级、AI 草稿管线。

宿主不提供、首版也不要求的：BI 资产模型、语义编译器、团队发布/协作契约、调度、查询取消/分页、绑定参数。
