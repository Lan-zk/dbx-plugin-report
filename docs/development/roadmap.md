# 开发路线图（M0–M4）

> 原则：**先确认原型，再证明闭环，然后做功能；每个里程碑有退出条件和止损门；不静默扩范围、不新增宿主 API。**  
> 本文件只管**范围与退出条件**；推进方式（阶段、轮次、每轮验证节拍）见 [delivery-plan.md](delivery-plan.md)。  
> 估算为 1 名熟悉前端与 SQL 的开发者的粗粒度 T 恤，不是承诺；实际以 M0 记录校准。  
> 当前状态：`P0 原型进行中（原型 v1 待确认）`、`M0 未开始`。

## 路线总览

| 里程碑 | 目标 | 主要交付 | 退出条件 | 止损门 | 粗估 |
|---|---|---|---|---|---|
| **P0** | 用静态 HTML 确认信息层级与交互入口 | `prototype/` 五屏可点击原型 + [prototype.md](prototype.md) + 评审清单 | 五屏在亮/暗下正常渲染；产品不变量各有可见落点；未决点已登记为决策 | 连续 3 轮改动仍无法收敛信息层级 → 降级为只定两屏（工作台/数据集） | 1–2 天 |
| **M0** | 证明 UI-only 闭环可行 | 最小 `.dbxp`：workbench + 连接选择 + `queryData` + 表格/柱状图 + `saveFile` JSON + 打开/重开（`fileTransfer.pick` + 分块 read） | 真机跑通“打开→执行→渲染→另存→重开→再执行”；打开失败分支（取消/超 5 MiB/非法 JSON）有状态；无 CSP/权限不可解阻塞 | 核心闭环在 3 天内无法跑通，且不能在不降低安全门槛下解决 → 停 | 1–3 天 |
| **M1** | 单报表竖切 | 文档格式 v0.1、单数据集固定 SQL、表格+柱状、运行/刷新、截断与错误状态、JSON 另存/打开（`fileTransfer`）、SQLite | V2/V3/V6 子集通过；2 名作者完成演练；无“假完整/假保存” | 作者拒绝文件式流程或 SQL 门槛 → 停/重做立项（D1/D2） | 5–8 天 |
| **M2** | 小看板 | ≤20 张报表（建议 ≤12）、同连接、逐卡刷新、每卡时间、部分失败（保留上次成功并标旧）、过滤器定义 + 显式映射 | 20 卡首屏 <1 s（懒渲染）、拖拽/缩放 60 fps；多卡刷新不阻塞 UI；失败不冒充最新；布局可拖拽/缩放/尺寸预设并保存/重开（12 列网格 + gridstack） | 多卡刷新/布局性能达不到目标且不能降级为分页看板 → 停，不扩宿主 | 4–6 天 |
| **M3** | AI 草稿（可选） | 受限 JSON 候选、schema/字段/版本校验、人工审阅、预览、手动保存 | V4 门槛：结构 ≥95%、语义 ≥90%、确认错误 0、注入 100% 阻止 | 未达标 → 移除 AI 卖点，保留手工工具 | 5–10 天 + 评估 |
| **M4** | PostgreSQL 认证 + 发布 | 方言 profile、黄金语料、跨库/时区/decimal 用例、打包签名、商店审核、SPDX | V3 全量 + V8 通过；商店审核/权限声明通过 | 任一库错误结果被标“完整” → 冻结发布；许可/审核不满足 → 停止分发 | 5–10 天 + 审核等待 |

## 关键路径与顺序

```
P0 (静态原型, 不连宿主)
  └─→ M0 (walking skeleton)
        └─→ M1 (single report, SQLite)
              ├─→ M2 (dashboard)
              └─→ M4 (PostgreSQL; 可与 M1 后半并行准备语料)
M3 (AI) 只在 M1 数据模型冻结后开始；不阻塞 M1/M2。
```

- **不要**跳过 P0 直接写实现再返工；**不要**先做看板再验证单报表；**不要**先做 AI 再做数据正确性。
- P0 不产生产品代码、不连宿主；其 token 镜像与组件 CSS 直接演进为 `ui/styles/`，避免二次实现。

- M1 结束前冻结 `ProjectDocument` v0.1；M2/M3 只能加字段，不能改语义。
- M4 的 PostgreSQL 语料与只读账号可在 M1 期间准备，但认证结论必须在 M4 给出。

| 门 | 决策 | 最晚时点 |

| D2 接受本机 JSON + 显式另存/重开 | 接受文件式资产 | 进入 M1 前 |

未拍板时仍可做 M0，但不得对外承诺 MVP 或排期 M1+。

## M0 任务书

见 [first-slice.md](first-slice.md)。技术栈已定（2026-10-22）：TypeScript + Vue 3.5 + Vite 8 + 自研轻量组件，看板画布用 gridstack 14（ADR-07），版本见 [tech-stack.md](tech-stack.md)；M0 需验证该文件 §7 的 9 项假设（含 20 卡布局引擎性能）与 `fileTransfer.pick/read/closeFileHandle` 打开路径（含取消/超限/句柄泄漏）。M0 结束产出 `docs/development/records/<date>-m0.md`：环境、命令、观察、截图/日志、go/no-go、对路线图的修正。

P0 确认后的信息层级、术语与组件视觉（[prototype.md](prototype.md)）是 M0 的实现起点，M0 不再重新讨论 IA；若实现中发现原型结论不可行，先改原型文档与 ADR，再改代码。

## M1 范围（单报表竖切）

**做**：
- 文档格式 v0.1（[data-model.md](data-model.md)）：datasets + reports；单连接；无 dashboard。
- 数据集：连接选择、固定 SQL、`maxRows`（≤5000）、运行/刷新、截断提示、错误状态。
- 报表：字段选择、表格/柱状、单位/时间口径说明、作者确认版本。
- 文件：JSON 另存（不返回路径）、`fileTransfer` 打开（pick + 分块 read，拖入增强）、≤5 MiB/未知 major/非法 JSON 校验、取消保存不置“已保存”。
- 指标词典：最小字段契约（单位、可加性、时间口径、NULL 策略）。

**不做**：看板、AI、PostgreSQL、dock/浮窗、PNG/SVG/PDF、SQL 参数、团队共享、自动刷新、任何文件导出（CSV 等，ADR-10）。

## M2 范围（看板）

- ≤20 张已确认报表（建议 ≤12），同一连接；逐卡排队（文档内≤2 并发）；每卡显示取数时间。
- 刷新策略：全刷 / 只刷可见 / 单卡刷；打开时自动取数由 `onOpenRefresh` 配置（默认关）；首屏只挂可见卡的图表（IntersectionObserver），离屏卡延迟渲染。
- 部分失败：其余卡可显示，看板标记“部分成功”；失败卡保留上次成功数据并标注旧数据时间，不沿用旧卡冒充最新。
- 过滤：过滤器完整定义（类型/必填/默认值/选项来源）+ 显式映射；只作用于已取回行，不宣称全库条件；未映射卡有角标。
- 布局编辑：12 列网格吸附 + **gridstack 14 官方 Vue wrapper**；拖拽/缩放、尺寸预设（1/3、1/2、2/3、整行 × 高 3/4/6/8）、紧凑排列；表单输入与键盘作为等价入口；持久化到 JSON，重开重新取数，不复用旧结果。
- 不做：像素级自由画布、跨看板/跨窗口布局继承、卡片分组/嵌套仪表盘；触发条件见 [tech-stack.md](tech-stack.md) §4.10 与 ADR-07。

## M3 范围（AI 草稿）

- 输入：连接摘要 + 已审核字段词典 + 作者目标；默认不发业务行。
- 输出：受限 JSON 候选（无 JS/URL/任意文件路径），schema/ID/版本/语法校验。
- 人工：审阅 → `queryData` 预览 → 核对口径/完整性 → 确认保存；取消/拒绝 0 自动查询/保存。
- 评估：V4 固定任务集（40 正常 + 20 对抗），模型/提示/词典 hash 留档；未达标移除 AI 承诺。

## M4 范围（发布）

- PostgreSQL 方言 profile、标识符/字面量/日期时间规则、允许特性；SQLite 回归。
- V3 全量：>5000 源行且 <5000 分组、5001 分组、NULL、decimal、DST、比率/去重、join 倍增、字段漂移；与独立客户端比对。
- V8：图表 JSON schema 负例、禁 URL/脚本、网络抓包、postMessage 来源、无 unsafe-eval、导出/日志扫描。
- 发布：`.dbxp`、签名/校验、引擎版本、权限最小化、SPDX/NOTICE、商店 PR、审核、回滚/卸载说明。
