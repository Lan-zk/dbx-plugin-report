# 测试策略

> 原则：**宿主契约由宿主测，插件正确性自己测；数据正确性优先于 UI；AI 不达标就下线。**  
> 基线：DBX b160d130；插件测试在代码建立后落地。

## 1. 测试分层

| 层 | 对象 | 方式 | 何时 |
|---|---|---|---|
| L0 宿主契约 | DBX 自身 plugin API/权限/数据限制 | 运行 DBX 仓库 155 项 Vitest + 可选 Rust 契约 | 升级 DBX 后、M0 前 |
| L1 单元 | schema 校验、hash、队列/代际、错误映射、格式化、CSV 转义 | Vitest（jsdom 不碰宿主） | 持续 |
| L2 集成 | 真机安装、授权、queryData、saveFile、result-view、workbench 复用 | 手工脚本化清单 + 截图/日志 | M0/M1/M2/M4 |
| L3 数据正确性 | SQLite/PostgreSQL 结果、类型、截断、边界 | 黄金 SQL 语料 + 独立客户端比对 | M1（SQLite）/M4（PG） |
| L4 AI 评估 | 候选 JSON 质量、拒绝率、人工耗时 | 固定任务集/模型/提示 hash | M3 |
| L5 安全 | 注入、外发、CSP、文档/CSV、日志 | 负例 + 抓包 + 代码审计 | M1 起持续，M4 发布门 |
| L6 发布 | 包、签名、权限、许可证、商店 | 打包检查 + 商店审核 | M4 |

## 3. 黄金数据与用例（V3）

### 3.1 SQLite 夹具

`fixtures/sales.db`：`orders`（≥10000 行）、`products`；字段含 `paid_at`、`status`、`amount`、`currency`、`region`、`product_id`。

| # | 用例 | 期望 |
|---|---|---|
| A01 | 月度聚合，源行 >5000，输出 <5000 组 | 正确聚合；不因源行多而截断 |
| A02 | 输出 5001 组 | `truncated=true`；显式样本；禁止“完整总计” |
| A03 | 单行结果 | 正常；表格/数值卡正确 |
| A04 | NULL 在维度/指标 | 按 SQL 语义展示；NULL policy 不伪造 0 |
| A05 | 金额 decimal/精度 | 与 sqlite3 输出一致；前端不丢精度/不显示错误小数 |
| A06 | 负数/退款 | 正确；指标口径说明可见 |
| A07 | 时间字符串/时区 | 按作者 SQL 输出；不前端猜时区 |
| A08 | 重复列名/别名大小写 | 与驱动一致；不合并/覆盖 |
| A09 | 宽表/大 cell 触发 8 MiB | 截断标记；不 OOM；不显示“完整” |
| A10 | 多语句 `SELECT 1;SELECT 2` | 被拒；错误可读 |
| A11 | 写 CTE/DDL/带副作用函数 | 被拒；不止依赖前端预检 |
| A12 | 注释/字符串里的关键字 | 不误判（按宿主分类器行为记录） |
| A13 | SQL 100001 字符 | 被拒/边界明确 |
| A14 | `maxRows` 0/1/5001/非整数 | 校验失败或夹紧；不越界 |
| A15 | 超时 SQL（sleep/大笛卡尔） | 超时错误；不假装取消数据库 |
| A16 | 列被删除/改类型后再打开 | stale/字段不匹配；列出受影响报表 |

### 3.2 PostgreSQL 追加

| # | 用例 | 期望 |
|---|---|---|
| P01 | `numeric(38,10)` 大数 | 精确展示，不用 JS number 丢精度 |
| P02 | `timestamptz` + DST 切换 | 与 psql 一致；不前端换算 |
| P03 | `date_trunc`/`generate_series` | 正常 |
| P04 | 标识符引号/大小写 | 与驱动一致 |
| P05 | schema/database 作用域 | 正确解析；不泄漏其他库 |
| P06 | 只读账号 + 写操作 | 数据库拒绝；插件正确展示 |
| P07 | 连接池已满/并发 4+ | 排队/拒绝明确；不无限重试 |

### 3.3 独立比对

- 每条黄金 SQL 同时用 `sqlite3`/`psql` 执行，记录列、行数、首尾值、checksum；插件结果必须一致（允许列顺序差异需显式）。
- 截断用例记录：宿主返回行数、`truncated`、是否命中行/字节/驱动上限（能区分的区分，不能区分就写“未知原因”）。

## 4. V4 AI 评估集

**正常任务 40**：单表聚合/时间趋势/Top N/比率/去重计数/多字段表 + 中文口径描述；覆盖不同字段类型与看板布局。
**对抗任务 20**：注入指令、伪造 schema、要求写操作、跨连接、要求全量导出、要求自动发布、超长/越界、冲突口径、缺失字段、诱导把 NULL 当 0、要求绕过授权。

**评分**：
1. 结构合法（schema/ID/引用/语法）自动判；
2. 语义正确（口径、字段、时间/货币/可加性）双人盲评；
3. 确认错误（数值/口径/安全）零容忍；
4. 人工耗时对比（无 AI vs AI）≥30% 降低。

**留档**：模型名/版本、prompt hash、词典 hash、任务集 hash、评分表；换模型必须重跑。

## 5. V8 安全用例

| 面 | 用例 |
|---|---|
| 图表配置 | 注入 `javascript:`、`<script>`、远程 URL、函数字段、超深嵌套 → 拒绝/转义 |
| 网络 | 抓包确认无外部请求；未声明 `host.network` 时 CSP 阻止 |
| iframe | 伪 postMessage 来源、嵌套 iframe、worker、form → 不执行 |
| 执行 | `unsafe-eval` 不存在；动态 `new Function` 禁用 |
| 文件 | 超大/深嵌套/`__proto__`/非 JSON → 拒绝；不读任意路径 |
| CSV | `=cmd`、`+`、`-`、`@` 开头转义；UTF-8/BOM 正确 |
| 日志 | 不含 SQL 字面量、结果值、token、连接串 |
| AI | 业务行未被发送（默认）；拒绝注入；不自动执行/保存 |
| 供应链 | SPDX/NOTICE、依赖许可证、签名/checksum、权限最小化 |

## 6. 自动化与手工边界

- **自动化**：L1 单测、schema/格式、CSV/格式化、错误映射、静态检查、打包校验。
- **手工/半自动**：M0/M1/M2 真机闭环、V3 数据库比对、V4 人工评分、V5 条件矩阵、V8 抓包/审计。
- 不在 CI 中跑真实 DBX UI；每个里程碑用 [acceptance.md](acceptance.md) 记录执行人/日期/证据。
- 已知 CI 不可覆盖的部分要在记录中明说，不能把“单测绿”当“集成通过”。

## 7. 退出标准

- M0：V1 + V2 最小闭环全过，无 P0 阻断。
- M1：V2/V3（SQLite A01–A16）/V6（round-trip/取消）/V8（M1 子集）通过，作者演练完成。
- M2：V2（多卡/部分失败）/V7（队列/资源）通过。
- M3：V4 全部门槛通过；否则移除 AI 承诺。
- M4：V3（PG 全量）+ V6 + V8 全量 + 发布检查通过；商店审核通过。
