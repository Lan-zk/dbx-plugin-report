# 宿主硬限制速查

> 这些是**边界**，不是待优化项。任何“绕过去”的方案都必须先过安全/口径评审，否则不做。  
> 基线：DBX b160d130 / Host API 1.4.0；详见 [capabilities.md](capabilities.md)。

## 1. 数据路径

| 限制 | 数值/规则 | 对 BI 的后果 | 应对 |
|---|---|---|---|
| 连接 | 一次一个 `connectionId`；必须已打开 | 不能跨连接 JOIN；不能替用户自动连接 | 单连接文档；打开时人工映射/授权 |
| 语句 | 一条，且被分类器判为只读 | 不能多语句/临时表/写操作；SELECT 也可能有副作用 | 作者固定 SQL；最小权限只读账号；反例语料 |
| 返回行 | 默认 500，最高 5000 | 明细无法全量展示；大表靠数据库聚合 | 聚合下推；把 5000 当结果上限而非输入上限 |
| 结果字节 | 序列化 rows 累计 8 MiB | 宽列/大 cell 会提前截断 | 控制 SELECT 列；提示用户；不按“峰值内存”承诺 |
| 结果截断 | 宿主返回 `truncated=true`（行数达上限或序列化字节超限）；不返回总行数，截断原因是否可区分未验证（H） | 只能按样本语义：不可当全集、不可给总数 | 常驻“已取回 N 行”；truncated 禁总计/占比/全量导出；M0 实测行 vs 字节触发 |
| SQL 长度 | 100000 字符 | 极少数大 SQL 受限 | 正常报表不会触及 |
| 超时 | 执行 timeout 配置上限 60 秒；非端到端 deadline | 慢查询可能排队/超时；关闭窗口不取消服务端 | 手动刷新；逐卡错误；不承诺 60 秒必返回 |
| 并发 | 每 bridge 4 个 data query | 超过会被拒绝 | 文档内队列≤2；看板 ≤20 卡（建议 ≤12）；显式排队状态 |
| 取消 | 无 `cancel`/`executionId` | “停止”只能丢弃旧响应并停后续调度，不能声称数据库已停 | 文案写“停止等待”；真正取消需宿主新增 API |
| 分页 | 无 cursor | 不能“取下一页”拼全量 | 不做分页明细/全量导出 |
| 参数绑定 | 无 bind | SQL 只能字符串内嵌；参数化需宿主 API 或严格类型编译+注入测试 | 首版不支持参数；作者改 SQL 重验 |
| 只读判定 | 分类器解析失败可能 fallback；函数黑名单有限 | “只读”不是无副作用证明 | 只读账号 + 固定 SQL + 不把分类当唯一防线 |

## 2. 元数据

| 限制 | 后果 | 应对 |
|---|---|---|
| 只能按已知表取列 | 不能枚举表/库/schema、不能发现主外键/关系 | 从当前表/作者输入表身份开始；不做自动建模 |
| 要求连接已打开且已有 metadata pool | 未打开/未加载元数据时可能失败 | 明确错误提示；先让用户在 DBX 中打开/浏览表 |
| 字段只有 name/type/nullable/length/precision/scale/default | 没有业务含义、单位、时间口径 | 指标词典由作者定义并版本化 |
| `field_capabilities` 可能为 unknown | 不能假设精度/长度可用 | 不猜；展示“未知”而不是默认值 |

## 3. 载体与资产

| 限制 | 后果 | 应对 |
|---|---|---|
| workbench 复用键含 connection，不含报表 id | 不能假定“打开另一份报表”会换 context | 文档 id 与 tab id 分离；一次只编辑一个文档 |
| result-view 快照 500 行、2 MiB | 只是“创建草稿”的入口，不是完整结果 | 保存前用 `queryData` 重新验证 |
| 浮窗同插件+workbench 贡献复用一个窗口 | 不是每份报表一个窗口 | 后续一个浮窗切换看板 |
| dock 不是 BI 布局引擎 | 看板布局/筛选/刷新仍由插件实现 | 首版不做 dock |
| storage 256 KiB/值、1 MiB 总量、1024 键、无 CAS | 不是资产库；多窗口可能覆盖 | 正式资产 JSON 文件；storage 只存偏好/草稿指针 |
| 保存对话框每次弹出、取消返回 null、**不返回路径**、无覆盖写 | 不能静默自动保存；不能“写回原文件”；无法在 UI 显示当前路径 | 显式保存；保存成功才更新状态；另存为唯一语义；文件名/时间可记，路径不记 |
| 文件读取：`fileTransfer.pick/read/drop`，无 manifest 权限，句柄 64，桥二进制 8 MiB/块 | 不能按路径直读/静默枚举目录；句柄泄漏会耗尽；每次须用户选择或拖入 | 打开走 pick + 分块 read + finally close；>5 MiB 文档拒绝；拖入作增强；不申请 `host.filesystem` |
| 无资产 API/无版本事务 | 没有服务器资产、没有 ACL、没有发布 | 本机文件 + 人工版本确认 |
| 无调度/通知 API | 不能后台定时刷新/订阅 | 手动刷新；无人值守不做 |

## 4. 元数据/AI/MCP

| 限制 | 后果 |
|---|---|
| AI completion 无工具、maxTokens 2048、输出 16k、单飞、逐次确认 | 只能生成小型候选，不能当 Agent 执行器/大看板生成器 |
| AI 对话不回传内容 | 不能靠聊天“保存”触发插件持久化 |
| mcp 最多 1 个且需 backend/opt-in | 不能“声明即工具可用”；MVP 不声明 |
| sidecar 反向只有 `host/requestUserInput` | sidecar 不能查宿主连接/schema/storage；自带连接等于重建连接管理 |
| 内置 Agent 只在 agent 模式合并插件工具 | Ask 模式不会调用插件工具；非只读工具逐次审批 |

## 5. 常见误读

1. **“5000 行限制让大表聚合不可行”**——错。限制的是返回行，数据库仍可扫描/聚合千万行。
2. **“60 秒上限是端到端 deadline”**——错。是执行 timeout 配置上限；排队/建池/传输不在同一 deadline 内。
3. **“8 MiB 是内存峰值”**——错。是序列化 rows 的累计上限。
4. **“只读分类通过就没有副作用”**——错。函数、UDF、方言差异都可能产生副作用；必须配只读账号。
5. **“列连接摘要=已授权查询”**——错。`connections:read` 只给脱敏摘要，查询另需 `data:read` + 用户 grant。
6. **“有 workbench 就有报表系统”**——错。窗口≠资产；报表对象、版本、口径都要插件自建。
7. **“支持 90+ 数据库=统一 BI 方言”**——错。API 有排除列表，SQL 语义/标识符/日期/数字行为差异大。
8. **“没有读取 API”**——过时。0.6.51 有 `fileTransfer.pick/read/drop`；但“能读”不等于“能按路径静默读”，每次都要用户选择/拖入。
9. **“保存对话框选同一文件就是覆盖”**——错。`saveFile` 不返回路径，也不保证覆盖写；把它当“已保存到原文件”会撒谎。

## 6. 必须新增 Host API 才能做的（进后续，不进首版）

- SQL 绑定参数（值/标识符分开的 bind）。
- 查询取消（`executionId` / cancel）。
- 分页/游标续读（cursor）。
- 表/对象枚举与主外键/关系元数据。
- BI 资产存储/版本/发布 API。
- 调度/订阅/通知。
- 团队 ACL/分享/审计。
- 打印/PDF 排版 API。
- 按路径直读与目录枚举（现在只有用户 `pick`/拖入产生的句柄）。

这些应作为**宿主路线图输入**正式提出；在插件侧只能降级，不能伪装支持。
